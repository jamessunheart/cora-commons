# Contributing

## The shortest path

1. Choose an open Need or create one using the issue form.
2. Discuss scope, acceptance evidence and expected return before substantial work.
3. Fork the repository and create one focused branch.
4. Submit the smallest useful artifact with tests or other evidence.
5. Request review from someone who did not produce the contribution.

## Pull request requirements

A pull request should state:

- the need and issue it addresses;
- what changed;
- how it was tested or otherwise verified;
- total known cost and unknown cost;
- limitations and risks;
- attribution for humans and agents involved;
- whether any reward was agreed in advance.

Passing automated checks means `WORKS` only for what those checks exercise. It does not establish real-world usefulness. Maintainers may merge a contribution only after independent review against the agreed acceptance conditions.

## Non-code contributions

Research, designs, referrals, compute, physical assets and services can begin as issues containing enough evidence for another person to inspect. Do not publish private records, credentials, contracts, beneficiary details or financial account information.

## Conduct

Be specific, kind and evidence-aware. Challenge ideas without attacking people. Disclose conflicts of interest. Do not manufacture users, endorsements, acceptance, savings or impact.
